# Совместимость тестов с Windows

- Тесты проекта должны проходить на Windows и Linux.
- POSIX-only модули (`fcntl`, `termios`, `pwd` и другие) нельзя импортировать безусловно. Используй capability-check и production fallback либо явный `skipif` для действительно POSIX-only поведения.
- Тесты lock/subprocess должны проверять платформенную ветку реализации, а cleanup должен работать без POSIX API на Windows.
- `os.kill(pid, 0)` нельзя использовать на Windows как безопасную проверку живого процесса; для этой цели используй `psutil.pid_exists()` или эквивалентный Windows API.
- Конкурентную замену общего файла на Windows выполняй под внутрипроцессной блокировкой и с ограниченным retry для кратковременного `PermissionError`.
- Для локальных запусков используй виртуальное окружение, UTF-8 и отдельную временную папку. Полный прогон по умолчанию выполняй в CI; длинные команды не запускай параллельно через Codex.
- Регрессия 2026-09-14: `tests/test_bot_main_event_loop.py` безусловно импортировал `fcntl` в `finally`; это ломало Windows после успешного сбора и прохождения части набора. Исправление использует `app.bot.lifecycle.fcntl` только при доступности.
- Итог проверки 2026-09-14: прежние перезапуски Codex были спровоцированы Windows-несовместимыми тестовыми/lock-сценариями и конкурентной atomic-записью; после исправлений Windows прогнал 913 тестов, coverage и параллельный `Promise.all` с успешным завершением.
