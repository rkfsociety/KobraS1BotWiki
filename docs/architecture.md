# Архитектура

## Как работает поиск

1. Из `WIKI_SITEMAP_URL` берётся список страниц; они скачиваются и кэшируются
2. Индексация идёт пакетами в фоне (`INDEX_BATCH_SIZE`, `INDEX_INTERVAL_SECONDS`)
3. Для русских вопросов при `RU_LAYER_ENABLED=true` запрос расширяется английскими ключевыми словами (`app/ru_layer.py`)
4. Считается похожесть (RapidFuzz `token_set_ratio`) + эвристики по модели принтера, URL и кодам ошибок
5. **Приоритет источников**: ручные Q&A → дизайн-справочник → каталог кодов ошибок → поиск по индексу вики
6. Если лучший результат ≥ `MIN_SCORE` — бот отвечает ссылкой
7. Если score между `CLARIFY_MIN_SCORE` и `MIN_SCORE` — задаётся уточняющий вопрос о модели принтера

## Локальные блокировки и atomic-write

- Lock-файл бота содержит PID текущего процесса. На POSIX живость PID проверяется через `os.kill(pid, 0)`, а на Windows — через `psutil.pid_exists(pid)`; Windows не использует POSIX-семантику сигнала `0`.
- На POSIX lock удерживается через `fcntl.flock`; на Windows используется fallback с проверкой PID и безопасным cleanup.
- Atomic-запись сначала создаёт временный файл рядом с целевым, затем заменяет целевой файл. Для конкурентных замен внутри процесса используется блокировка и ограниченный retry на Windows при временном `PermissionError`.
- Тесты этих веток не должны зависеть от фиксированных индексов handlers и не должны безусловно импортировать POSIX-only модули.

## Единое хранилище данных

Единственная рабочая база бота — `data/chat.sqlite3`. Процесс создаёт один
экземпляр `ChatStore` и передаёт его обработчикам, веб-панели и Mini App.
Входящие и исходящие Telegram-сообщения, Mini App-обмены, статистика,
очереди разбора, ручные ответы, feedback, фиксы, контекст, модерация,
админская активность, лента ответов и сессии панели хранятся в этой базе.
Старые JSON-файлы читаются только при первом запуске для одноразовой миграции
в таблицу `bot_state`; новые изменения в них не записываются.

Индекс вики, каталоги и экспортные JSON остаются файловыми артефактами, а не
операционным состоянием бота.

## Данные и кэш

| Путь | Содержимое |
|------|-----------|
| `data/chat.sqlite3` | Единственная рабочая база: сообщения, состояния модулей, AI-темы и legacy-baseline; файл и WAL/SHM не коммитятся |
| `.cache/db-backups/` | Ежедневные проверенные копии базы; не коммитятся |
| `data/*.json`, `.cache/*.json` | Legacy-источники миграции, индекс/кэш или экспорт; рабочие данные после миграции не сохраняются в них |
| `logs/bot.log` | Ротируемый лог решений бота |
| `sitemap.xml` | Снимок карты сайта вики (для справки; рабочий URL — `WIKI_SITEMAP_URL`) |
