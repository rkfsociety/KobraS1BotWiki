# Конфигурация (.env)

Обычные параметры задаются в `.env`, а секреты — в отдельном `.env.secrets` рядом
с ним. Шаблоны — `.env.example` и `.env.secrets.example`. Секретный файл не
коммитится и загружается раньше `.env`, поэтому его значения имеют приоритет.
На Linux ограничьте доступ к нему: `chmod 600 .env.secrets`.

## Обязательные

| Переменная | Где задавать | Описание |
|-----------|--------------|---------|
| `TELEGRAM_BOT_TOKEN` | `.env.secrets` | Токен бота из @BotFather. **Никогда не коммитить.** |
| `WIKI_BASE_URL` | `.env` | Базовый URL вики (например `https://wiki.anycubic.com`) |
| `WIKI_SITEMAP_URL` | `.env` | URL sitemap.xml вики |

## Поиск и пороги

| Переменная | Где задавать / значение по умолчанию | Описание |
|-----------|--------------------------------------|---------|
| `MIN_SCORE` | `72` | Порог совпадения (0–100). Много ложных — поднять. |
| `CLARIFY_MIN_SCORE` | `55` | Порог для уточняющего вопроса о модели принтера. |
| `CLARIFY_ENABLED` | `true` | Задавать уточняющий вопрос при «почти уверенном» score. |
| `QUESTIONS_ONLY` | `true` | Отвечать только на вопросы (с «?» или вопросительными словами). |
| `REQUIRE_TRIGGER` | `true` | Для не-вопросов требовать @бота или reply на бота. |
| `RU_LAYER_ENABLED` | `true` | Расширять русские запросы английскими ключевыми словами. |

## ИИ и дневные темы

Команда доступна только администраторам и должна быть ответом на сообщение пользователя.
Бот передаёт LiteRouter текст сообщения и найденные фрагменты вики, а ответ публикует
reply на исходное сообщение. Автоматические ответы бота команда не меняет. Ежедневная
статистика использует тот же LiteRouter для группировки сохранённых сообщений предыдущего
дня; результат сохраняется в `data/chat.sqlite3` отдельно для каждой группы и даты.

| Переменная | Где задавать / значение по умолчанию | Описание |
|-----------|--------------------------------------|---------|
| `LITEROUTER_ENABLED` | `true`, если задан ключ | Включить команду `/ii`. |
| `LITEROUTER_API_KEY` | `.env.secrets` | API-ключ LiteRouter; не Git и не логи. |
| `LITEROUTER_BASE_URL` | `https://api.literouter.com/v1` | OpenAI-compatible base URL LiteRouter. |
| `LITEROUTER_MODELS` | `deepseek-v4-flash:free,gpt-oss-120b:free,glm-5.3-flash:free,glm-5.2:free` | Модели по порядку: первая основная, следующие — fallback при ошибке, таймауте или пустом ответе. |
| `LITEROUTER_MODEL` | — | Совместимость со старой настройкой: если задана, используется только эта модель и список игнорируется. |
| `LITEROUTER_TIMEOUT_SECONDS` | `25` | Таймаут запроса к провайдеру. |
| `LITEROUTER_COOLDOWN_SECONDS` | `9` | Минимальная пауза между запросами к общему тарифу LiteRouter, включая fallback и параллельные `/ii`; `0` — отключить. Значение 9 даёт запас относительно минимальных 5 секунд тарифа. |
| `LITEROUTER_MAX_TOKENS` | `0` | Лимит генерации в токенах. `0` — не передавать искусственный лимит провайдеру; длинный результат бот разбивает на сообщения Telegram до 4096 символов каждое. |
| `LITEROUTER_CONTEXT_DOCS` | `3` | Сколько найденных статей передавать модели. |

При включённом LiteRouter бесплатная `:free` модель сначала решает, является ли сообщение вопросом. Только после
решения `QUESTION` обычный обработчик ищет подходящую страницу в индексе вики, а если надёжный результат не найден,
передаёт модели текущий вопрос и до 50 предыдущих сообщений
того же `chat_id` и `message_thread_id`. Сообщения из других тем в этот контекст не попадают.
Порядок моделей для classifier и ответа совпадает с приоритетом ежедневной тематизации (`TOPIC_MODEL_PRIORITY`);
при ошибке или некорректном ответе используется следующая модель из списка.

Для ночной тематизации бот один раз запрашивает `GET /models`, выбирает доступные
бесплатные модели из встроенного рейтинга и пробует их последовательно. При ошибке,
таймауте или невалидном JSON используется следующая модель; если список моделей
получить не удалось, сохраняется fallback из `LITEROUTER_MODELS`.

## Доступ и чаты

| Переменная | По умолчанию | Описание |
|-----------|-------------|---------|
| `ALLOWED_CHAT_IDS` | _(все)_ | Где бот может отвечать в группах: список chat_id через запятую. Пусто = отвечать во всех группах. Личные чаты с ботом всегда разрешены. |
| `ALLOWED_TOPIC_IDS` | _(все)_ | Где бот может отвечать в темах форума: список topic_id (пусто = все темы разрешённых чатов). На личные чаты не влияет. |
| `DAILY_STATS_TOPIC_ID` | `0` | Тема ежедневной статистики: `0` — общая тема без передачи `message_thread_id`, положительное число — конкретная тема форума. |
| `REQUIRE_CAN_REPLY` | `false` | Проверять `getChatMember` перед обработкой. |
| `DEVELOPER_USER_IDS` | — | Дополнительные user_id разработчиков: служебные команды как у админа. |
| `EPHEMERAL_EXEMPT_CHAT_IDS` | — | Чаты, где не автоудалять пару «команда + ответ». |

## Поведение в группах

Бот собирает входящую статистику и текстовые вопросы из всех групп и тем, сообщения которых Telegram ему доставляет, независимо от `ALLOWED_*`. Эти списки ограничивают только исходящие ответы: вне разрешённого чата/темы бот молчит, но вопрос попадает в общую очередь `missed_questions` в `data/chat.sqlite3` для последующего разбора.

| Переменная | По умолчанию | Описание |
|-----------|-------------|---------|
| `REPLY_REVIEW_MENTION` | `off` | Username (без @) — добавлять в конце ответа для уведомления. |
| `REACTION_LOG_ADMIN_ONLY` | `1` | Логировать реакции 💩/👎 только от админов. |
| `NEGATIVE_REACTION_EMOJIS` | `💩 👎` | Набор «плохих» эмодзи для логирования. |

## Фильтр болтовни

Бот автоматически молчит на нетехнический чат (реализовано в `app/bot/text_heuristics.py`):

- Сравнения принтеров, обсуждение покупки б/у, планы печати
- Статусы («запускаю первый слой», «запустился в многоцвет»)
- Сарказм, риторические вопросы, мнения в треде
- Числа/символы без слов («35?», «40%?»)
- Короткие анафорические вопросы без 3D-контекста («А зачем он?»)
- Болтовня о ПК, алкоголе, сне — вне темы печати
- Запросы мастера по ремонту в городе, соцсети

При `LOG_DECISIONS=true` причина молчания видна в `logs/bot.log` как `skip reason=conversational_chatter`.
