# Веб-панель администратора

Встроенная панель (`app/web_panel.py`) запускается в фоновом потоке внутри процесса бота — отдельный сервис не нужен. Включается при `PANEL_ENABLED=true` или автоматически, если задан `PANEL_PASSWORD` в `.env.secrets`.

## Возможности

- **Дашборд** — лента последних ответов бота с кнопкой «Отметить ошибочным» (⚑), статус, размер индекса, ключевые параметры
- **Ошибочные ответы** — список помеченных ответов (`data/bad_answers.json`); кнопка «Обработано» удаляет запись
- **Ручные Q&A** — просмотр / добавление / редактирование / удаление `data/manual_qa.json` (аналог `/qaadd`, `/qalist`, `/qadel`); правки сразу применяются без перезапуска
- **Фиксы ссылок** — управление переопределениями (`fixes.json`, аналог `/fix`)
- **Логи** — хвост `logs/bot.log` с фильтром по подстроке
- **Обновление** — «Проверить обновления» (git fetch) и «Обновить» (git pull + перезапуск)
- **Настройки** — редактирование `.env` прямо из браузера (кроме токена бота)

## Telegram Mini App

Mini App открывается по адресу `/app`, например:
`https://kobras1bot.duckdns.org/app`.

Это одно приложение для настроенных групп. При открытии Telegram `initData` проверяется на сервере, затем бот через `get_chat_member` проверяет членство пользователя в `PANEL_ADMIN_CHAT_ID`. Участник получает пользовательскую сессию; `creator` и `administrator` получают также роль администратора.

В пользовательской сессии доступен только чат. В админской сессии доступны также дашборд, дневная статистика группы, модерация, поиск по вики и очередь вопросов без ответа; администратор может добавить ручной ответ или отметить вопрос оффтопом — изменения сразу попадают в общие данные бота.

Вкладка **«Статистика»** показывает сводку за выбранную дату (по умолчанию сегодня): общее число входящих сообщений участников и, если они есть, до трёх тем с количеством сообщений по ним. Ответы бота, названия моделей и заголовки страниц вики в эти темы не попадают; отдельные метрики ответов бота остаются доступными отдельно. Данные разделяются по группе и теме форума; хранится окно последних 31 дней. Если настроено несколько групп, над сводкой появляется выбор группы; по умолчанию выбирается `Official Anycubic Russia` (`-1002295062981`), если этот чат есть в `ALLOWED_CHAT_IDS`. API `GET /api/app/stats?date=YYYY-MM-DD&chat_id=<id>` принимает только чат из настроенного списка и доступен администратору Mini App.

Та же сводка доступна командой `/stats` в личном чате бота или администратору в разрешённой группе/теме, где бот может отвечать. В группе команда показывает текущую тему, в личном чате — группу из `PANEL_ADMIN_CHAT_ID`. Для просмотра другого дня можно добавить дату: `/stats 2026-09-11`.
Начальная и конечная фразы сводки выбираются случайно при каждом формировании сообщения; доступно по 500 уникальных вариантов каждого типа. Число сообщений склоняется автоматически (`1 сообщение`, `2 сообщения`, `5 сообщений`). Ответ `/stats` не удаляется автоматически.

Вкладка **«Модерация»** показывает последние события `ban/kick/mute/unban`, предупреждения и действия над сообщениями для настроенной группы, а также известный текущий список забаненных или замьюченных пользователей. Список строится по событиям `ChatMemberUpdated`, сохранённым ботом; Telegram Bot API не предоставляет общего метода для выгрузки всех банов и мутов группы. Временные ограничения отображаются до указанного срока.

Исполнительные команды модерации вызываются в самой группе администратором ответом на сообщение пользователя: `/ban`, `/unban`, `/kick`, `/mute [30s|10m|2h|3d]`, `/unmute`, `/warn`, `/unwarn`, `/warnings`, `/clearwarns`. Команды `/del`, `/pin` и `/unpin` также требуют reply на сообщение. У бота должны быть соответствующие права администратора; предупреждения хранятся отдельно в `.cache/moderation.json` и не применяют автоматическое наказание без отдельной команды.

Для безопасности `/ban`, `/kick` и `/mute` перед действием повторно проверяют статус цели и не применяются к владельцу или администратору группы. Если статус цели не удалось проверить, команда отменяется.

### Пользовательский режим и история чата

Кнопка **«Режим пользователя»** в админском Mini App открывает предпросмотр того, что видит обычный участник. В этом режиме можно отправить вопрос боту и проверить пользовательский сценарий; админский дашборд и очередь при этом скрыты. Администратор может вернуться кнопкой **«Режим админа»**.

Единая история сообщений и агрегаты Telegram-статистики хранятся локально в базе SQLite `data/chat.sqlite3`.
Сообщения Telegram дополнительно разделяются по `chat_id` и `topic_id`, а
история Mini App — по Telegram ID пользователя. Пользовательский endpoint
истории возвращает только персональную переписку текущего пользователя.
База и её WAL/SHM-файлы не должны попадать в git.

Endpoint’ы пользовательского чата:

- `GET /api/app/chat/history` — возвращает историю текущего пользователя; поддерживает `limit` (от 1 до 50) и необязательный `before_id` для подгрузки более старых сообщений.
- `POST /api/app/chat/message` — принимает поле формы `text` размером до 32 KiB, атомарно сохраняет вопрос и ответ бота и возвращает пару сообщений с `duplicate` и `rate_limit: {short_remaining, window_remaining}`. Для обоих endpoint’ов требуется Bearer-сессия Mini App.

Ограничения отправки применяются отдельно для каждого Telegram ID: не более одного сообщения за 3 секунды и не более 20 сообщений за 10 минут. `short_remaining` — секунды до следующего нового запроса, `window_remaining` — число оставшихся запросов в десятиминутном окне. Повтор того же текста с уже сохранённым ответом в течение 10 секунд создаёт новую запись вопроса, возвращает переиспользованный bot-ответ с `duplicate: true`, не запускает повторный поиск и не расходует новый rate-limit event.

Источники истории: пользовательские сообщения имеют `source="miniapp"`; ответы бота — `manual`, `wiki`, `missing` или `error`.

Если ручной ответ или достаточно точное совпадение вики не найдены, бот возвращает короткий fallback о невозможности ответить, сохраняет этот ответ в истории с источником `missing` и добавляет исходный вопрос в очередь `missed_questions`. Администратор разбирает очередь через `GET /api/app/missed`, а результат добавляет ручной ответ или отмечает вопрос оффтопом.

Обычный участник группы может получить пользовательскую Mini App-сессию, но не имеет доступа к админским данным: запросы к `/api/app/dashboard`, `/api/app/missed` и операциям очереди требуют роли администратора группы и для обычного участника возвращают `403`. Таким образом, админский dashboard и endpoint’ы `missed` не видны и недоступны обычному участнику.

Устаревшие `GET /api/app/search` и `POST /api/app/question` сохранены только для админского предпросмотра и также требуют роли администратора.

Чтобы `/start` показывал кнопку открытия приложения, задайте:

```dotenv
PANEL_WEBAPP_URL=https://kobras1bot.duckdns.org/app
```

## Вход

### Через Telegram-бота (рекомендуется)

Не требует домена — работает на «голом» IP:порт.

1. На странице входа нажать «Войти через Telegram-бота»
2. Откроется `t.me/<бот>?start=<код>` — нажать **Start**
3. Бот через `get_chat_member` проверяет, что пользователь — **админ группы** `PANEL_ADMIN_CHAT_ID`
4. Код одноразовый, живёт 5 минут, привязан к браузеру

### По логину/паролю (запасной)

Активен только если задан `PANEL_PASSWORD` в `.env.secrets`. Членство в группе не проверяется.

### Login Widget (опционально)

Endpoint `/tg-auth` поддерживает классическую кнопку «Log in with Telegram». Требует домен — в @BotFather → `/setdomain`. На «голом» IP не работает.

## Настройки панели

| Переменная | Где задавать / значение по умолчанию | Описание |
|-----------|--------------------------------------|---------|
| `PANEL_ENABLED` | `true` если задан пароль | Включить панель. Для TG-входа без пароля задайте явно `true`. |
| `PANEL_TG_LOGIN` | `true` | Вход через Telegram. |
| `PANEL_ADMIN_CHAT_ID` | `-1003881305021` | Группа, чьи админы могут входить. `0`/`off` — выключить TG-вход. Также используется как fallback для статистики, если `ALLOWED_CHAT_IDS` не задан. |
| `PANEL_PASSWORD` | `.env.secrets` | Пароль запасного входа. Пусто = только через Telegram. |
| `PANEL_USERNAME` | `admin` | Логин запасного входа. |
| `PANEL_HOST` | `0.0.0.0` | Адрес прослушивания. `127.0.0.1` — только локально. |
| `PANEL_PORT` | `8080` | Порт. |
| `PANEL_SESSION_TTL_SECONDS` | `86400` | Срок жизни сессии (секунды). |
| `PANEL_WEBAPP_URL` | — | HTTPS-адрес Mini App; при задании появляется кнопка в `/start`. |

## Безопасность

- TG-вход: проверка HMAC-подписи + членство в админах группы
- Сессия: cookie (`HttpOnly`, `SameSite=Lax`)
- Формы: CSRF-токен
- Вход: троттлинг (8 неудач за 5 минут → пауза)
- Mini App: HMAC-проверка `initData`, короткая Bearer-сессия, повторная проверка админского статуса на сервере
- Панель работает по **HTTP** — при доступе снаружи закройте reverse-proxy с HTTPS (nginx/Caddy); это заодно даёт домен для `/setdomain`
